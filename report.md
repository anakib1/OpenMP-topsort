# Паралельна реалізація топологічного сортування з використанням OpenMP та MPI

## Анотація

У цьому звіті представлено порівняльний аналіз двох паралельних реалізацій алгоритму топологічного сортування з використанням OpenMP та MPI. Реалізації були протестовані на орієнтованих ациклічних графах (DAG) різних розмірів, від 100 до 20 000 вершин. Результати демонструють значні відмінності в продуктивності між двома підходами, причому MPI показує кращу продуктивність у всіх тестових випадках.

## 1. Вступ

Топологічне сортування є фундаментальним алгоритмом у теорії графів з застосуванням у плануванні завдань, розв'язанні залежностей та системах збірки програм. У цьому дослідженні реалізовано алгоритм з використанням двох різних парадигм паралельного програмування:

- OpenMP: Модель паралельного програмування зі спільною пам'яттю
- MPI (Message Passing Interface): Модель паралельного програмування з розподіленою пам'яттю

## 2. Деталі реалізації

### 2.1 Огляд алгоритму

Алгоритм топологічного сортування складається з таких основних кроків:
1. Обчислення вхідних степенів для всіх вершин
2. Ініціалізація стеку вершинами з нульовим вхідним степенем
3. Обробка вершин по порядку, оновлення вхідних степенів сусідів
4. Додавання вершин до результату, коли їх вхідний степінь стає нульовим

### 2.2 Реалізація OpenMP

Реалізація OpenMP розпаралелює два основні компоненти:
- Обчислення вхідних степенів за допомогою `#pragma omp parallel for`
- Обробка вершин з атомарними операціями для потокової безпеки

Ключові особливості:
```cpp
#pragma omp parallel for
for (int u = 0; u < numVertices; ++u) {
    for (int v : graph[u]) {
        #pragma omp atomic
        ++inDegree[v];
    }
}
```

### 2.3 Реалізація MPI

Реалізація MPI розподіляє робоче навантаження між кількома процесами:
- Кожен процес обробляє підмножину вершин
- `MPI_Allreduce` об'єднує обчислення вхідних степенів
- Процес 0 координує загальне виконання

## 3. Експериментальне середовище

### 3.1 Тестове середовище
- Операційна система: macOS 24.1.0
- Компілятор: Apple Clang 16.0.0
- Версія OpenMP: libomp 20.1.2
- Реалізація MPI: Open MPI 5.0.7

### 3.2 Тестові випадки
- Розміри графів: 100, 1 000, 10 000 та 20 000 вершин
- Кожен тест повторювався 5 разів
- Тести MPI виконувались з 4 процесами

## 4. Результати та аналіз

### 4.1 Порівняння продуктивності

Середній час виконання (в секундах):

| Розмір графу | OpenMP    | MPI       | Прискорення |
|--------------|-----------|-----------|-------------|
| 100          | 0.346136  | 0.000674  | 513.55x     |
| 1 000        | 0.345562  | 0.000806  | 428.73x     |
| 10 000       | 0.347692  | 0.001677  | 207.33x     |
| 20 000       | 0.357718  | 0.000785  | 455.69x     |

### 4.2 Ключові спостереження

1. **Продуктивність MPI**: Реалізація MPI стабільно перевершує OpenMP на кілька порядків.

2. **Масштабованість**:
   - OpenMP показує відносно стабільну продуктивність для різних розмірів графів
   - MPI зберігає відмінну продуктивність навіть на більших графах

3. **Стабільність часу виконання**:
   - OpenMP показує варіації між 0.31-0.39 секунд
   - MPI підтримує більш стабільний час виконання, зазвичай менше 0.001 секунди

### 4.3 Аналіз результатів

Значна перевага в продуктивності MPI може бути пояснена:
1. Ефективним розподілом робочого навантаження між процесами
2. Зменшеною конкуренцією порівняно з синхронізацією спільної пам'яті
3. Кращим використанням кешу завдяки архітектурі розподіленої пам'яті

## 5. Висновки

Експериментальні результати демонструють, що:
1. Реалізація MPI забезпечує кращу продуктивність для топологічного сортування
2. Підхід з розподіленою пам'яттю ефективніше обробляє графи
3. Модель спільної пам'яті OpenMP має обмеження в цьому конкретному застосуванні

## 6. Майбутня робота

Потенційні напрямки вдосконалення включають:

3. Дослідження шаблонів використання пам'яті
4. Оптимізацію шаблонів комунікації в реалізації MPI
